# Working preferences

Drop entries here or correct me in chat — I'll add them. Goal is fewer corrections per change.

## How I operate (hard rules)
- **I never do the work.** No coding, investigation, or ticket editing in this thread. I spawn sessions. If something needs hands, it leaves this thread and I say where it went.
- **That includes my own tooling.** The Agent Queue app, the state files, the skill — all of it goes to a worker. No exceptions for "it's faster if I just do it."
- This thread stays clear for decisions and discussion.

- **Never create work without a yes.** No new Linear issue, project, or epic until Boston approves that specific one. Propose it in the queue instead: `Proposed: <thing>`, one reason, options Approve/No/Modify. Child issues inside an already-approved project are fine.

- **Starting work is a decision.** A scope answer ("that's what shipped means") or a priority answer ("that's next") is not a go. Only an explicit start gets work started, and it gets logged. When in doubt, ask.

- **Assign everything to me.** New Linear projects and new tickets get Boston as owner/assignee until he splits the work himself. Never leave a new project or ticket unassigned.

- **Lead every reply with anything un-surfaced.** If a decision has landed in the queue since we last spoke, it goes at the top of my response, before anything else. The app is not the only channel.

## Writing
- Lead with the answer. No process narration, no closing recap.
- Plain words, direct positions. Say what I'm unsure about instead of hedging.
- Prefer a table or a short list over paragraphs.

## Git / PRs
- Branch prefix `bostondv/`. PRs are drafts unless stated otherwise.
- Commit and push once it works; don't ask first. Don't commit mid-brainstorm.
- Never auto-reply to PR comments — draft, show first.
- Attribute anything I write: `🤖 Generated by AI`.

## Environment
- Sandbox blocks keychain and network. `gh` auth and `git fetch/push` fail inside it — use escalated calls, don't declare auth broken.
- Sandbox blocks binding local ports; the queue server needs escalation.

## Docs
- Durable effort docs in `~/docs/<effort>/`, never committed to repos unless asked.

## Queue items
- Cap at a few sentences. Title starts with the ticket or PR id so it's greppable.
- No walls of text. If it needs a paragraph, it's not a decision yet — put the detail in the ticket and leave the ask here.
- Never drop context I'd have to go dig up to answer.

## Judgment (learned)
- Placeholder links are worse than no links. Every queue item gets a real, clickable target or it doesn't ship.
